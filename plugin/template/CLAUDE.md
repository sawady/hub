# {{HUB_NAME}} — engineering hub of {{OWNER}}

This repo has no product code. It is where work across several repos is planned, where agents are
launched on those repos, and where everything that happens is recorded. Notes are written in {{LANG}}.

## Sources of truth

- `progress.md` is THE source of truth for what is going on: Now, Next, Blocked, Paused, Done and a
  "Resume here" block that lets anyone (a person or a fresh session) pick up the work.
- `repos.md` maps every repo this hub drives: alias, path, base branch, forge (GitHub or GitLab),
  and the commands to check it. Each repo also has its own `CLAUDE.md` / `AGENTS.md`: **read it
  before editing that repo**.
- `features/<name>.md` holds the context of each feature that spans repos: the contract between
  repos, the PR/MR table, merge order, e2e test plan and decision log. Read it before touching code
  for that feature.
- `journal/YYYY-MM-DD.md` are optional daily notes, written by `/hub:close`.
- `research/` holds investigations that are not (yet) features.

When something relevant happens (a PR/MR opened or merged, a decision, a blocker), update
`progress.md` and the feature file **in the same turn**. Dates are always absolute (YYYY-MM-DD),
never "today" or "last Tuesday".

## Working a feature end to end

1. `/hub:feature <name>` creates `features/<name>.md` from `features/_template.md`.
2. **Contract first:** write the contract between repos (endpoints, payloads, semantics, errors)
   in the feature file and get it approved before any code is written.
3. `/hub:e2e <name>` implements it in parallel: one subagent per repo, each in its own
   `git worktree` so the branch you have checked out is never touched. Producers go before
   consumers (e.g. the API that generates a client before the app that uses it). The results are
   checked against the contract.
4. Before a PR/MR leaves draft it goes through code review and the feature's e2e checklist.
5. PRs/MRs are opened as drafts. Merging needs an explicit OK from {{OWNER}} (`/hub:merge`).

## Rules for agents

- Work on branches, never directly on a repo's base branch. Never force-push unless a rebase was
  asked for. Never merge without an explicit OK.
- Working files shared between parallel agents (PR descriptions, notes) are named after the branch
  or PR (`pr-<branch>.md`), never generic names like `pr.md`.
- Never run anything that writes to production. If a task needs production data, ask.
- Metrics are per repo and per team, never per person.
